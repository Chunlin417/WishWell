# 接上 Supabase 服务器

不配置也能用：没有服务器地址时，庭院用这台设备的 localStorage（只有自己的牌和香，没有别人）。配置之后，所有人共用一个庭院——能看到别人的木牌和香，规则（名字固定、半小时一块、每天三块、一人一炷香、100 个插位）由服务器判断。

## 你要做的（约 10 分钟）

1. 到 <https://supabase.com> 注册，新建一个项目（Region 选离用户近的，比如 Tokyo 或 Singapore）。
2. 左边栏 **Authentication → Sign In / Providers**（或 Settings），打开 **Allow anonymous sign-ins**。
3. 左边栏 **SQL Editor** → New query，把 [`supabase/schema.sql`](../supabase/schema.sql) 整段粘贴进去，点 Run。可以重复运行。
4. 左边栏 **Project Settings → API**，复制 **Project URL** 和 **anon public key**。
5. 在项目根目录新建 `.env.local`（已被 .gitignore 忽略），写入：

   ```
   VITE_SUPABASE_URL=https://你的项目.supabase.co
   VITE_SUPABASE_ANON_KEY=你的 anon key
   ```

6. 重启 `npm run dev`。打开浏览器控制台，看到 `庭院数据： 服务器` 就连上了；看到 `本机` 说明没配置或连不上（控制台有原因）。

部署到静态网站托管时，同样的两个变量要配在托管平台的环境变量里（构建时读取）。

## 它是怎么保证规则的

- anon key 是公开的，所以三张表都开了行级安全且**没有任何策略**：浏览器不能直接读写表。
- 浏览器只能调三个函数：`get_state`（读）、`add_plaque`（挂牌）、`light_incense`（点香）。规则和时间（`now()`）都在函数里判断，改本机时钟没用。
- 同一个人的两次请求用咨询锁串行，不会同时通过"半小时一块"的检查。
- 愿望文字从头到尾不会发到服务器：服务器只收到名字，日期由服务器按用户时区算。

## 还没做 / 要注意

- **没有在真实的 Supabase 项目上测过**：SQL 和客户端是对照文档写的，浏览器里用一个模拟的服务器验证了客户端的逻辑（时钟偏差、规则被拒绝、断网、别人挂牌后木牌不跳位）。第一次连真服务器时如果报错，把控制台的信息发给我。
- **同一台设备清缓存或换浏览器 = 新的匿名身份**：可以重新取名、再点一炷香，旧的牌还在树上但不再是"你的"。要找回需要以后加账号绑定。
- **防刷靠匿名登录本身的限流**：Supabase 对匿名登录有按 IP 的频率限制（控制台 Authentication → Rate Limits 里可以调）。需要更严的话可以打开 CAPTCHA。
- **名字没有敏感词过滤**，只限制了长度和去掉控制字符。
- **木牌只读最近 300 块**；树上挂点现在 59 个，满了要扩展（以后的事）。
- **国内访问**：Supabase 在大陆有时慢或连不上。连不上时客户端会自动退回本机数据，不会白屏。
